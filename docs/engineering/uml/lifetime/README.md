## 관계를 읽는 규칙

- **값 포함**: JSON 필드·배열·스냅샷. 같은 내용이 보고서·이력·작업 결과에 복사될 수 있으므로 객체의 독점 소유를 주장하지 않는다.
- **참조**: ID·파일 키·root UUID·경로 조합. 대상이 삭제되어도 참조 값이 남을 수 있다. DB FK 유무와 실제 파일 존재를 별도로 적는다.
- **수명 관리**: 생성한 timer·process·WebView를 명시적으로 정리하는 책임. 프로세스의 비정상 종료까지 완벽히 보장한다는 뜻은 아니다.
- `-->`는 값/참조 association, `..>`는 변환·사용 dependency, `*--`는 생성·정리 소유가 확인된 경우만 사용한다. 이번 조사에서 빈 다이아몬드 **aggregation은 사용하지 않는다**. 단순 필드 참조를 aggregation으로 바꿀 근거가 없다.
- 다중성은 **주체 하나가 가리키는 대상 수**다. 그림은 대상 쪽에만 다중성을 붙인다. 참조하는 주체의 역방향 개수나 모든 JS 객체의 독점 소유를 추정하지 않는다. `0..1`은 필드 부재 또는 참조 대상 유실을 포함하며 표에서 구분한다.
- 흐름도의 디스크·실행 범위 노드는 실제 클래스가 아닌 자원/함수 실행 범위다. 정식 UML 배포·컴포넌트 표기라고 부르지 않는다.

## 중요한 결과와 판단

**사실:** Clip의 구간·분석·태그는 D1 clips의 JSON 값으로 저장된다. pc_jobs.clip_id에는 FK가 없고 클립 삭제가 작업행 삭제를 수행하지 않는다. PC 원본과 분석 checkpoint·완료 export도 클립 삭제/취소 시 자동 삭제되지 않는다. 임시 staging/frames는 별도 정리 대상이다. Activity.pendingShare의 링크와 ID는 preferences/Bundle 값으로 복원된다.

**해석:** 보관함 데이터의 수명, 영속 작업의 수명, OS 파일의 수명, 화면 객체의 수명을 네 층으로 읽어야 한다. 하나의 거대한 composition 트리로 합치면 현재 구현과 어긋난다.

## 검증과 미확인

각 문서의 표에 파일·심볼·SQL/호출 근거를 남겼다. 문서 링크·표·공개 정보·코드 불변 결과는 [검증 기록](../validation.md)에 기록한다. 기존 환경에 Mermaid 파서/CLI가 없어 편집 가능한 소스와 관계를 수동 대조했으며 **자동 파싱·시각 렌더링은 미검증**이다. 이번 조사에서 삭제·강제종료·실기기 재생성 실험은 하지 않았다. 파일 정리 실패와 알려진 운영 제한은 [운영 문서](../../local-video-ingestion-operations.md), 실제 서비스 검증 상태는 [구현 기록](../../local-video-ingestion-progress.md)을 따른다.
