# 태깅의 정의

각 클립의 시각적 특징을 분석하여, 사전에 정의된 태그 분류 체계의 각 효과와 유사도를 계산한다. 

각 속성에는 기준값 이상의 유사도를 가진 태그가 0개 이상 부여될 수 있으며, 

하나의 클립에는 서로 다른 속성과 동일 속성의 여러 태그가 동시에 부여될 수 있다. 

각 태그에는 효과의 표준 명칭과 분류, 유사도 점수, 동의어 및 상·하위 관계가 함께 저장된다.

예를 들어 한 클립이 이렇게 분류될 수 있다

| 속성 | 태그 | 유사도 |
|---|---|---:|
| Visual Style | Digital Glitch | 0.94 |
| Visual Style | VHS | 0.71 |
| Transformation | RGB Split | 0.91 |
| Transformation | Channel Shift | 0.78 |
| Motion Style | Jitter | 0.84 |
| Texture | Noisy | 0.69 |
| Compositing | Ghosting | 0.62 |

## 내부적 정의

| 종류 | 예 | AI 판단 |
|---|---|---|
| **Observable Tag** | Glitch, RGB Split, Jitter, Grainy | 영상에서 직접 판단 |
| **Inferred Tag** | Fractal Noise, Rotoscoping, Tracking | 영상에서 추정 |
| **Manual Tag** | 사용자가 실제 제작법을 알고 입력 | 확정 정보 |

UI에서는 전부 태그처럼 보여도 되지만 DB에는 confidence와 source를 따로 둬야 해.

예를 들어:
{
  "tag": "Rotoscoping",
  "confidence": 0.64,
  "source": "ai_inferred"
}

와
{
  "tag": "Rotoscoping",
  "confidence": 1.0,
  "source": "user"
}

는 의미가 상당히 다르지.

## 규칙 1

효과 이름은 반드시 표시 이름과 내부 ID를 분리하는 게 좋아

예를 들어 사람마다
RGB Split
RGB Shift
Color Split
Channel Split
RGB Separation
Chromatic Split

등으로 부를 수 있다.

서비스 내부에서는 하나의 canonical tag를 정한다.
id: transformation.rgb_split

display_name:
RGB Split

aliases:
RGB Shift
RGB Separation
Color Separation
Channel Separation

그러면 사용자가 검색창에 rgb separation이라고 입력해도 RGB Split으로 연결할 수 있어.

## 규칙 2

태그는 계층 구조가 있어야 한다

Glitch
Digital Glitch
Analog Glitch
Datamosh
Pixel Sorting
Compression Artifact
Signal Error
RGB Split

을 전부 같은 레벨에 놓으면 검색이 어려워져. 실제 후보군에도 이들이 한 그룹으로 모여 있다.

내부적으로는 이런 식의 계층을 만드는 게 좋아.
Glitch
│
├─ Digital Glitch
│  ├─ Datamosh
│  ├─ Pixel Sorting
│  ├─ Compression Artifact
│  └─ Block Artifact
│
└─ Analog Glitch
   ├─ Signal Error
   ├─ Static
   └─ Scanline

모든 관계를 꼭 부모-자식으로 만들 필요는 없어.

RGB Split
related_to → Glitch

Chromatic Aberration
related_to → RGB Split

같은 related 관계도 두면 좋다.
