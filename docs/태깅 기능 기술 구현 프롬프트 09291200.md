# 태깅 체계 v2 전환 작업

현재 구현은 `legacy/분류 후보군.md`를 기준으로 만들어졌다.
이제부터 태깅·검색·저장과 관련된 기존 요구사항은 아래 v2 기준으로 대체한다.

이번 작업은 문서만 수정하는 작업이 아니다.
현재 구현을 조사하고, 실제 런타임과 데이터 구조가 v2 태그 체계를 사용하도록
필요한 코드·DB·API·UI·테스트를 끝까지 수정하라.

단, 기존에 정상 작동하는 영상 등록, 클립 생성, 파일 저장 기능은 불필요하게
다시 작성하지 말고 태깅 체계와 연결 지점만 안전하게 마이그레이션한다.

## 기준 문서 우선순위

서로 다른 내용이 있을 경우 다음 순서로 판단한다.

1. `taxonomy/taxonomy.v2.yaml`
   - 런타임에서 사용하는 canonical 태그 사전의 단일 기준본
2. `taxonomy/taxonomy.schema.json`
   - 태그 사전의 유효성 검증 규칙
3. `태깅 기능 구체화.md`
   - 태그의 의미, 출처, 계층 및 운영 원칙
4. `구현 범위 요약 개정판.md`
   - 서비스 범위와 사용자 흐름
5. `분류 후보군_개정판.md`
   - 태그 사전의 기획 원본
6. `legacy/*`
   - 과거 맥락을 확인하기 위한 참고 자료일 뿐 구현 기준으로 사용하지 않음

`legacy/분류 후보군.md`를 읽는 코드가 있다면 제거하거나 v2 loader로 교체한다.
기존 파일은 기록 보존을 위해 삭제하지 않는다.

## 목표

기존의 단순 태그 문자열 목록을 다음 특성을 가진 canonical taxonomy로 전환한다.

- 변경되지 않는 canonical ID
- 사용자에게 보여주는 display name
- 검색어 정규화를 위한 aliases
- namespace별 분류
- parent 및 related 관계
- observable 여부
- 자동 확정 가능 여부
- taxonomy version
- AI 관찰, AI 추정, 사용자 입력의 구분
- 하나의 클립에 0개 이상의 복수 태그 지원
- 같은 namespace 안에서도 복수 태그 지원

## 필수 namespace

다음 12개 namespace를 지원한다.

- `visual_style`
- `generation_method`
- `production_technique`
- `transformation`
- `motion_style`
- `texture`
- `geometry_pattern`
- `compositing`
- `color`
- `shot_type`
- `camera_motion`
- `subject`

`motion_style`은 피사체와 화면 요소의 움직임이고,
`camera_motion`은 카메라 또는 가상 카메라의 움직임이다.
두 분류를 합치지 않는다.

## 핵심 불변 규칙

1. DB 저장, API 요청·응답, 검색 필터에는 `display_name` 대신 `tag_id`를 사용한다.
2. AI는 `taxonomy.v2.yaml`에 존재하지 않는 `tag_id`를 생성할 수 없다.
3. 적합한 태그가 없으면 빈 배열을 반환할 수 있어야 한다.
4. AI가 발견했지만 사전에 없는 특징은 태그로 저장하지 않고
   `unclassified_observations`에 별도로 기록한다.
5. `observable: true`는 화면에서 직접 관찰한 결과로 다룬다.
6. `observable: false`는 제작 방법을 확정하지 않고 `ai_inferred`로만 다룬다.
7. `auto_accept_allowed: false`인 태그는 점수가 높아도 자동 확정하지 않는다.
8. 사용자가 추가하거나 승인한 태그는 이후 AI 재분석으로 덮어쓰거나 삭제하지 않는다.
9. 사용자가 거절한 AI 태그도 저장하여 재분석 시 같은 제안을 반복하지 않게 한다.
10. 모든 분석 결과에 사용한 `taxonomy_version`, 모델, 프롬프트 버전을 저장한다.
11. AI가 반환하는 score는 보정된 확률로 간주하지 않는다. 초기에는 `ai_score`로 저장한다.
12. alias는 검색 입력을 canonical ID로 변환할 때 사용한다.
13. 같은 display name이 여러 namespace에 존재할 수 있으므로 이름만으로 태그를 병합하지 않는다.

## 태깅 결과 모델

태깅 결과는 최소한 다음 구조를 표현할 수 있어야 한다.

```json
{
  "clip_id": "clip_123",
  "taxonomy_version": "2.0.0",
  "analysis_run_id": "analysis_456",
  "tags": [
    {
      "tag_id": "visual_style.digital_glitch",
      "ai_score": 0.94,
      "source": "ai_observed",
      "status": "suggested",
      "evidence_ms": [500, 1500]
    },
    {
      "tag_id": "production_technique.rotoscoping",
      "ai_score": 0.64,
      "source": "ai_inferred",
      "status": "suggested",
      "evidence_ms": [1500]
    }
  ],
  "unclassified_observations": []
}
